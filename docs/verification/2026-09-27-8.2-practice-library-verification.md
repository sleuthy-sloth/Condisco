# 8.2 verification — independent practice library

**Date:** 2026-09-27
**Scope:** plan 8.2 — an on-device reading library for learner-provided plain
text: import (paste + file), selection→save into the existing phrasebook and
review scheduler, document deletion that spares learning events, and export
round-trip. Four implementation slices, each gated fresh before the next began.
**Design source:** `docs/reviews/2026-09-27-8.2-practice-library-design.md`
(fix-71, 12 sections + corrections; reconciled spot-check: all cites accurate).
**Plan done-when:** "user-provided material remains private and usable offline,
imported phrases enter the existing review scheduler without duplicate keys,
and deleting a document removes its local copy without erasing unrelated
learning events." Mapping in the Verdict section below.

## Slice 3 — Library UI (fix-74)

- **Surface:** `ReviewSection.library` in ContentView (segment order Review |
  Saved | Library; default still `.review`); new `Condisco/Lesson/LibraryView.swift`:
  document list (language · characters · Imported date per §9.2), empty state
  (EmptyStateView, `art: .phrases`), toolbar "+" and empty-state "Add text"
  import menu → paste sheet (UIPasteboard, explicit tap) / `fileImporter`
  `[.plainText, .utf8PlainText]`; `LibraryImportPreviewView` confirm sheet
  (editable title, 5-slug language picker, §7 privacy line); reader =
  selectable `UITextView` representable with debounced selection (§6.1 —
  SwiftUI `.textSelection` ruled out by design); floating "Save phrase" for
  non-empty selection ≤ 200 chars → save sheet (meaning **required**, exact
  copy "Add what it means so this phrase can be reviewed.", source = document
  title read-only); Save = `savePhrase` + `linkPhrase`, link last; delete =
  the app's **first destructive-confirm** (`confirmationDialog`,
  `.destructive`, "The text is removed from your library. Phrases you saved
  from it stay in your Phrasebook.").
- **Logic seams (UIKit-free):** `LibraryLanguage`, `LibraryImport` (single
  validator gateway, title heuristic, selection trim/cap),
  `@MainActor LibrarySavePhrase.commit`.
- **Tests:** +7 (`LibraryCommitTests` — import commit/rejection paths, title
  fallback, selection boundaries, save-sheet commit with empty pack sources).
- **Gate defects:**
  - **D5** build failure (type-check, not parse — `swiftc -parse` passes
    legitimately on both): `importMenu` took a plain generic `label: Label`
    while both call sites passed closure literals (→ `() -> some View`
    non-conformance), and the generic named `Label` shadowed SwiftUI's
    `Label` view (→ "Label has no member init"). Fixed: `@ViewBuilder label:
    () -> MenuLabel`, generic renamed; both call sites unchanged.
  - **D6** `testDocumentTitleFromFileURLStripsExtension` —
    `title(fromFileURL: URL(fileURLWithPath: "/tmp/"))` returned "tmp"
    (Foundation's `lastPathComponent` on a directory URL) instead of the
    designed fallback. Fixed with a `hasDirectoryPath` guard → "Pasted text"
    (design §5: "file name minus extension, or 'Pasted text'"; real picker
    path unaffected — `.plainText` UTType cannot match directories).
- **Slice gate:** fast gates green; combined suite **548/0 unit + 6/0 UI
  TEST SUCCEEDED** (`82-slice3-test-fix2.log`).
- **Flagged deviations:** §9.2 explicitly defers the per-document
  "Saved phrases" section — v1 reader is content + selection + save button;
  empty-state "Add text" is a Menu (two options) styled identically to
  EmptyStateView's action button because EmptyStateView accepts only a
  plain-button closure; reader uses `navigationDestination(for:)` on the
  existing NavigationStack (iOS 16 pattern already used throughout); paste
  reads UIPasteboard only on explicit tap — the app's first and only
  (offline) pasteboard use.
