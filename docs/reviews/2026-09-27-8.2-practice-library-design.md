## 1. Scope & non-goals

**In scope (v1)**
- Import a learner's own material as UTF-8 text, by file picker or by pasting,
  into an on-device reading library, with a size limit and safe rejection of
  unsupported/undecodable/oversized input.
- Read an imported document; select a phrase; save it into the existing
  phrasebook (`saved_phrases`) with a deterministic dedup id; have that saved
  phrase enter the existing review scheduler (FSRS via the event log) and
  appear in the Review tab queue.
- Preserve title, import date, and the learner's own content locally.
- Delete a document (with a destructive confirm) exactly as far as its own
  rows, leaving unrelated learning events untouched.
- Privacy: user material never leaves the device except through the app's
  existing explicit, user-initiated exports.

**Non-goals**
- **No audio import.** Deferred to a later, device-gated phase: audio-file
  import lands only after text import and the player-resume behavior
  (`listen_state`, `LearningStore.swift:372-377, 1220-1275`) are proven on
  device. This design adds no audio path of any kind.
- **No network and no AI.** There is no network code in the app today
  (verified: zero `URLSession`/http references in `Condisco/`). There is no
  AI-feedback feature, so the plan's "no AI upload" requirement is currently
  vacuous; the design keeps it that way by adding no new network surface and
  no remote path.
- **No new languages.** Documents are tagged only with the five bundled course
  languages (`CourseLanguage`, `Condisco/Models/CoursePack.swift:83-110`).
- **No dictionary service.** There is no offline dictionary for arbitrary
  user text (see §6); v1 meaning is learner-supplied.
- **Offline-first.** Everything reads/writes `Documents/verbalibera.sqlite`
  through `LearningStore.inDocuments()` (`LearningStore.swift:426-432`).

## 3. Data model

### 3.1 New tables (additive DDL)

Schema evolution today is: `CREATE TABLE IF NOT EXISTS` in a single
`db.exec` block in `LearningStore.init` (`LearningStore.swift:345-401`), plus
column additions via a `PRAGMA table_info` probe + `ALTER TABLE … ADD COLUMN …
NOT NULL DEFAULT ''` migration for *existing* tables (the `saved_phrases`
`source_pack_id`/`source_lesson_id` migration, `LearningStore.swift:403-415`).
The new tables are brand new, so **only the `CREATE TABLE IF NOT EXISTS` arm
is needed** — existing databases gain them on next launch with zero ALTERs and
zero changes to `saved_phrases`/`events`/`checkpoints`/`kv`/`sync_uploads`
column sets. This mirrors how `listen_state` and `saved_phrase_tombstones`
were added.

```sql
-- Added to the init DDL block (LearningStore.swift:345-401), after
-- saved_phrase_tombstones.
CREATE TABLE IF NOT EXISTS imported_documents(
  id TEXT PRIMARY KEY,              -- UUID().uuidString
  title TEXT NOT NULL,              -- editable at import; "Untitled" fallback
  content TEXT NOT NULL,            -- UTF-8 text, validated before insert
  byte_size INTEGER NOT NULL,       -- original UTF-8 byte count (limit display)
  language_slug TEXT NOT NULL,      -- one of the five CourseLanguage slugs
  source_file_name TEXT NOT NULL DEFAULT '',  -- file name for file imports; ''
                                          -- for paste
  imported_at_ms INTEGER NOT NULL   -- import date, preserved for display
);
CREATE INDEX IF NOT EXISTS idx_imported_docs_time
  ON imported_documents(imported_at_ms, id);

CREATE TABLE IF NOT EXISTS imported_phrase_links(
  phrase_id TEXT NOT NULL,          -- == saved_phrases.id
  document_id TEXT NOT NULL,        -- == imported_documents.id
  PRIMARY KEY (phrase_id, document_id)
);
```

Design decisions behind the shape:

- **No foreign keys.** The store opens with `PRAGMA foreign_keys = ON`
  (`Database.swift:39`) but the existing schema declares zero FKs and manages
  referential integrity with explicit `DELETE` statements inside
  `db.transaction` blocks (e.g. `clearCheckpoint`,
  `LearningStore.swift:767-790`). Following that convention avoids the
  insert-ordering foot-gun a real FK would create in `applyImport` (links must
  merge after their phrases) and keeps restore/merge code identical in shape
  to today's. Cleanup is explicit: `unsavePhrase` and document deletion both
  delete their link rows (§8, §3.3).
- **Computed size, stored byte count.** `content` is stored as the validated
  String and `byte_size` stores `content.data(using: .utf8)!.count` so the UI
  can show "1 MB" provenance without re-measuring, and so a future "total
  library size" line is a single `SUM`.
- **`language_slug` required.** Refusing a language at import keeps the
  phrasebook's per-language grouping honest (`SavedView.swift:117-128` groups
  by `languageName`) and keeps the review card's TTS resolvable
  (`ShadowVoice.languageCode(for:)`, `Condisco/Listen/ShadowMode.swift:13`).
- **What is *not* stored:** no listen/audio fields, no file-modified dates
  (the plan preserves the *import* date), no encryption (the SQLite file is
  already the app's plaintext store; the export file inherits today's
  behavior).

### 3.2 Store API (signatures; implementation later)

```swift
// LearningStore additions (new MARK section "Imported documents")
struct ImportedDocument: Hashable, Identifiable, Sendable {
    var id: String
    var title: String
    var content: String
    var byteSize: Int
    var languageSlug: String
    var sourceFileName: String
    var importedAt: Date
}

func saveDocument(_ doc: ImportedDocument) throws            // INSERT, ON CONFLICT(id) DO NOTHING
func documents() throws -> [ImportedDocument]                // ORDER BY imported_at_ms DESC, id
func document(id: String) throws -> ImportedDocument?
func deleteDocument(id: String) throws                       // §8 transaction
func documentIDs(forPhrase phraseId: String) throws -> [String]

// Phrase provenance (called from the save-phrase sheet)
func linkPhrase(phraseId: String, documentId: String) throws // INSERT OR IGNORE
```

`saveDocument`/`deleteDocument` take `db.transaction` exactly like
`savePhrase` (`LearningStore.swift:1288`).

### 3.3 Provenance and the document↔phrase link

`saved_phrases` has no document column and gains none (additive constraint is
not the reason — a nullable column *would* be additive — but the link is
many-to-many: the same deduped phrase can be saved from two documents and also
from a lesson, and a phrase's provenance is not a single source). Instead, a
joining table `imported_phrase_links(phrase_id, document_id)` records "this
phrase was saved from this document". No `ALTER TABLE saved_phrases` at all, so
`StoredSavedPhrase`/`SavedPhrase`/sync/export shapes are untouched.

The phrase row itself keeps `source = <document title>` — it already carries a
free-text source label displayed by the Phrasebook (`SavedView.swift:246-250`),
so saved phrases read the same whether they came from a lesson or a document.
`sourcePackId`/`sourceLessonId` stay **empty** for document-sourced phrases so
the phrasebook's "open the source lesson" tap (`SavedView.swift:267-284`)
never deep-links into a document that is not a bundled lesson.

Cleanup rules on the link table:
- `unsavePhrase(id:)` (`LearningStore.swift:1319-1338`) additionally executes
  `DELETE FROM imported_phrase_links WHERE phrase_id = ?` inside its existing
  transaction — a phrase removed from the phrasebook must not leave dangling
  links.
- Document deletion removes that document's links (§8).

## 4. Review-scheduler integration

### 4.1 What the code actually supports (verified)

- The Review tab's only queue source is `ReviewCatalog.loadDue`
  (`ReviewModels.swift:135-157`): it projects each bundle pack with
  `store.project(pack:)` and resolves every due evidence key back to an
  **authored** activity via `makeItem` (`ReviewModels.swift:165-205`).
  `makeItem` returns nil — silently dropping the key — when no
  `pack.activities` entry matches (`:169-173`). Saved phrases have no authored
  activity and are not SRS items today: `project(pack:)` builds `evidence`
  only from `attempt` events whose keys resolve to pack activities
  (`LearningStore.swift:1729-1756`, revalidation at `:1484-1495`).
- There is **no existing phrase-review surface** anywhere: the `.saved`
  segment is the read-only Phrasebook (`ContentView.swift:147-154`; trash is
  fire-and-forget, `Phrasebook.swift:220-228`). Nothing in the review flow
  consumes `saved_phrases`.
- A synthetic in-memory `CoursePack` is not viable without invasive model
  changes: `CoursePack` and every nested model are decode-only (`let` fields +
  custom `init(from:)`, e.g. `CoursePack.swift:12-80`, `Activity` `:661-763`,
  `GradedBase` `:341-372`); none has a memberwise initializer, and five of the
  bundled languages plus Home/widget/`ReviewModel` load packs through
  `PackLoader.loadPacks()` (`PackLoader.swift:62-64`).

**Therefore the mechanism is: a small phrase-review projection that reuses the
existing scheduler's exact FSRS fold and the existing review item/session
pipeline, not a new parallel scheduler and not a fake pack.**

### 4.2 Mechanism

New file `Condisco/Review/LibraryReview.swift` (pure logic, no UI; testable
exactly like `ReviewCatalog`):

```swift
enum LibraryReview {
    static let packId = "practice-library"      // pack_id on phrase-review attempt events
    static let packVersion = "1"                // stable; carried on events

    // One phrase row ⇔ one evidence key ⇔ one FSRS chain.
    static func evidenceKey(phraseId: String) -> String { "phrase-review|\(phraseId)" }

    // The same fold project(pack:) runs for lesson evidence
    // (LearningStore.swift:1729-1756): correct/incorrect outcomes only,
    // Fsrs.initial / Fsrs.scheduleReview / Fsrs.grade, keyed by evidence key.
    static func project(attempts: [ActivityAttempt]) -> [String: EvidenceRecord]

    // ReviewItem built from a saved phrase; TTS resolvable via
    // ShadowVoice.languageCode(for: phrase.languageSlug).
    static func makeItem(phrase: SavedPhrase, dueAt: Date,
                         presentationOrdinal: Int) -> ReviewItem

    static func loadDuePhrases(phrases: [SavedPhrase], attempts: [ActivityAttempt],
                               now: Date = Date()) -> (due: [ReviewItem], nextDueAt: Date?)
    static func loadTrickyPhrases(phrases: [SavedPhrase], attempts: [ActivityAttempt]) -> [ReviewItem]
    static func countPhrasesDueWithin(phrases: [SavedPhrase], attempts: [ActivityAttempt],
                                      days: Int, now: Date = Date()) -> Int
}
```

Wiring (the only Review-tab change):

- `ReviewModel.reloadScoped()` (`ReviewView.swift:76-85`) additionally reads
  `store.allEventsWithQuarantine()` (`LearningStore.swift:1183-1187`),
  filters `.attempt` events to `packId == "practice-library"`
  (tolerant read: a corrupt row is logged via the existing
  `LearningStore.logCorruptRows` path, same as `loadTricky`,
  `ReviewModels.swift:273-280`), dedupes candidate phrases by joining
  `saved_phrases` to `imported_phrase_links`, and merges the phrase items into
  `due`, `tricky`, and `dueTomorrowCount`. The merged list is sorted by
  `dueAt` together with the lesson items, preserving the existing
  oldest-first contract.
- Verdicts need **zero** changes: `ReviewModel.recordVerdict`
  (`ReviewView.swift:135-145`) records `store.record(.attempt(item.makeAttempt(verdict:)))`
  and the phrase `ReviewItem` reuses `ReviewItem.makeAttempt`
  (`ReviewModels.swift:83-107`), so a phrase verdict lands in the same
  append-only log and reschedules through the same FSRS.
- `ReviewSessionView` (quiz / flashcards / handsfree) is untouched; library
  items are ordinary `ReviewItem`s. The flashcard and hands-free modes
  surface library phrases too — a free, coherent win of reusing the surface.

Scope semantics (deliberate, asserted by tests):

- **All-courses scope** includes the library stream; the review card header
  shows `courseTitle = phrase.languageName`, `lessonTitle = phrase.source`
  (the document title), so provenance is visible on the card.
- **Focus-course scope** excludes it (the library is not a course; the scope
  resolves to a bundled pack id, `ReviewView.swift:114-123`). Documented
  behavior, not an omission.
- **Home's Today count, the widget due count, You-screen due counts, review
  reminders, and lesson warm-ups stay on bundled packs only.** They all call
  `ReviewCatalog.loadDue(packs: PackLoader.loadPacks(), …)` independently
  (`HomeView.swift:39,72`; `WidgetSnapshotWriter.swift:75`;
  `ReviewReminders.swift:107-109`; `LessonPlayerView.swift:1189` warm-up must
  never surface learner-only phrases). The library stream is added only inside
  `ReviewModel`. This is a scoping line the orchestrator can sanity-check;
  widening it later is a single call-site change.

### 4.3 Dedup story (explicit)

1. **Phrase identity** is the existing deterministic `savedPhraseId`
   (`LearningStore.swift:1282-1284`): `"\(languageSlug)|\(target)|\(meaning)"`
   — the TEXT PRIMARY KEY of `saved_phrases`, so a re-save is
   `ON CONFLICT(id) DO NOTHING` (`:1293`).
2. **Evidence identity** is `phrase-review|<phraseId>`, a pure function of the
   phrase id. Saving the same phrase twice — same document, another document,
   or after unsave+resave — always produces the same evidence key, hence one
   item in the queue and one FSRS chain. No duplicate cards, no duplicate
   keys, by construction; this is asserted by a test that saves twice and
   checks `savedPhrases().count == 1` and a single due item.
3. Same target, different meaning → different id → two phrases, two keys. This
   matches the existing phrasebook semantics and is not a regression.
4. **Events are append-only** (`LearningStore.swift:305-310, 479-483`), so a
   phrase's review history never duplicates or vanishes; unsave→resave resumes
   the old FSRS state (continuity, not duplication — the same behavior a
   CloudKit replay has).

## 5. Import flow

### 5.1 Entry points

- **File picker:** `fileImporter(isPresented:allowedContentTypes:allowsMultipleSelection:onCompletion:)`
  mirroring `YouView.swift:66-71`, with `allowedContentTypes:` limited to
  `[.utf8PlainText, .plainText]` (with `.text` allowed and then validated, or
  simply restricted — the picker restriction is the first defense, the
  validator the second). Reads security-scoped data exactly like
  `YouView.importSelectedFile` (`YouView.swift:751-767`).
- **Paste:** a new `TextEditor`-based sheet (no `UIPasteboard` usage exists in
  the app; this is the first, and it is used only to pre-fill the editor,
  never to read wirelessly). The pasted string is converted to `Data` and run
  through the same validator.

### 5.2 New `LibraryImportValidator` (mirrors `ImportValidator`)

`ImportValidator` (`Condisco/Store/ImportValidator.swift`) validates *exports*;
the library import is a different contract (raw text), so the type is new and
parallel, but it copies the discipline: pure, side-effect-free, plain-language
errors for direct display, and a named pinned size constant
(`ImportValidator.maxImportSizeBytes = 50 * 1024 * 1024` at
`ImportValidator.swift:98` is the precedent — export files are multi-year
logs; a *single reading document* needs far less).

```swift
enum LibraryImportError: Error, CustomStringConvertible, Equatable {
    case tooLarge(actualBytes: Int, limitBytes: Int)
    case notUTF8
    case empty
}

enum LibraryImportValidator {
    /// Named and pinned so the bound is auditable, like maxImportSizeBytes.
    static let maxDocumentBytes = 1 * 1024 * 1024   // 1 MB
    static func validate(_ data: Data) -> Result<String, LibraryImportError>
}
```

Checks, in order, with exact-style copy (matching the plain tone of
`ImportValidator.swift:66-90`):

1. `data.count <= maxDocumentBytes` else
   "This text is too long to import (the limit is 1 MB)."
2. `String(data: data, encoding: .utf8)` must succeed else
   "This file isn't readable as UTF-8 text. Nothing was imported."
   (This is the safe rejection for undecodable/binary/garbage input; a
   non-text UTType that slips past the picker dies here.)
3. trimmed content non-empty else
   "There's no text here to import."

**Limit rationale:** 1 MB of UTF-8 is on the order of 300k+ words — far beyond
a realistic reading passage for practice — while staying comfortably below any
SQLite row-size concern (the default SQLITE_MAX_LENGTH is 1 GB) and keeping
the reader view and the `content` column predictable. It is one named constant
in one file, trivially raised later. At the limit the learner gets the plain
error above and nothing is written.

### 5.3 Confirmation sheet (reuses `ImportPreviewView` pattern)

An `ImportPreviewView`-style sheet (`YouView.swift:795-859`: `NavigationStack`,
counts, a plain "what this does" paragraph, bottom-anchored primary action)
showing, for a library import: the editable title field (pre-filled with the
file name minus extension, or "Pasted text"), the language picker (five
`CourseLanguage` slugs; default = `condisco.focusLanguage`
`UserDefaults`), character/byte count, and the privacy line:

> "This text stays on this device. It is never synced or sent anywhere unless
> you export your data yourself."

Primary action "Add to library" runs `saveDocument`. The plan's title/imported-
date preservation is satisfied by the `title` (editable) and `imported_at_ms`
columns.

## 6. Lookup & save flow

**Verified reality:** there is no offline dictionary for arbitrary text. The
only "lookup" that exists is the per-passage *authored* glossary of bundled
sustained material (`Condisco/Lesson/Glossary.swift` — pack vocabulary maps;
`SustainedGlossaryPanel`, `StimulusViews.swift:864-922`). That glossary cannot
exist for the learner's own documents, so the plan's "look up selected
phrases" is implemented honestly as: **select → the learner supplies the
meaning → save**. No dictionary lookup is claimed, no translation service is
added.

v1 interaction in the document reader:

1. The reader renders `content` in a `UITextView` wrapper
   (`UIViewRepresentable`; UIKit interop is already normal in this app,
   e.g. `UIFontMetrics` in `DesignTokens`). A plain SwiftUI
   `.textSelection(.enabled)` (the precedent is `SustainedGlossedBody`,
   `StimulusViews.swift:1044`) is *not* enough — SwiftUI never hands the
   selected substring back to the app — so the representable reports
   `textViewDidChangeSelection` (debounced) and exposes `selectedRange`.
2. When the selection is a non-empty span (≤ 200 chars), a floating
   "Save phrase" button appears.
3. Tapping it opens a save sheet pre-filling `target` with the selected text
   (editable), `meaning` with an empty field, `source` with the document
   title (read-only), `languageSlug` from the document.
4. **Meaning is required** (Save disabled until non-empty, with copy "Add what
   it means so this phrase can be reviewed."). This is not cosmetic: an empty
   meaning would (a) produce a review card with an empty answer, and (b) fold
   every identical-target save in one language into the single dedup key
   `"\(slug)|\(target)|"` — collapsing meanings a learner typed on purpose.
   Keeping meaning in the key preserves the existing dedup contract
   (`savedPhraseId` has always included meaning), and library saves are the
   only surface where an empty meaning was possible, so the check is new,
   local, and cheap.
5. Save runs `store.savePhrase(...)` + `store.linkPhrase(...)` in one
   transaction; a clone sheet writing both is the implementation note. The
   link insert is `INSERT OR IGNORE`, so re-saving the same phrase from the
   same document is a no-op everywhere.

Meaning edits after save are out of scope: editing the meaning would change
the deterministic id and create a second phrase row — identical to today's
phrasebook behavior (no meaning editing exists anywhere). The sheet's
pre-filled, editable meaning is the one place v1 lets the learner correct it.

## 8. Deletion semantics

### 8.1 Exact rows removed

`deleteDocument(id:)` runs one transaction executing exactly:

```sql
DELETE FROM imported_phrase_links WHERE document_id = ?;
DELETE FROM imported_documents WHERE id = ?;
```

That is the entire surface. **Not** touched: `events` (append-only by
invariant, `LearningStore.swift:305-310`), `saved_phrases`,
`saved_phrase_tombstones`, `checkpoints`, `checkpoint_tombstones`,
`listen_state`, `kv`, `sync_uploads`. No tombstone is written and none is
needed: documents never sync, so nothing can resurrect them remotely (unlike
phrases/checkpoints, `LearningStore.swift:256-263, 767-790`).

### 8.2 Position: what happens to phrases saved *from* the document

**Position: the phrase and its review history survive; the queue stops
scheduling it.** Deleting a document removes its link rows, so the phrase drops
out of the review queue (candidates are link-joined, §4.2) but stays in the
Phrasebook, and every phrase-review event stays in the log.

Justification:

- The phrasebook is the learner's explicit collection; the trash button there
  (`Phrasebook.swift:220-228`) is the only way a phrase should ever vanish —
  deleting reading material must not silently censor a phrase the learner
  chose to keep.
- The queue reflects *live* documents: the Review tab never shows a card whose
  header cites a deleted source document (stale-provenance cards are worse
  than none).
- Nothing is erased: re-importing the same text and re-saving the phrase
  recreates the link and resumes the exact FSRS schedule, because the evidence
  key is a pure function of the phrase id (§4.3).
- Done-when (c) holds literally: the delete removes the document's local copy
  and erases no learning events — phrase-review events, other documents'
  events, checkpoints, and phrasebook rows are all untouched. A test asserts
  the exact row counts before/after.

### 8.3 Destructive-confirm UX

This is the app's **first** destructive confirm (verified: zero
`confirmationDialog` and zero `role: .destructive` anywhere in the tree). It
establishes the pattern: a `confirmationDialog` on the document row's trash

## 11. Risks & open questions for the developer

1. **DataExport inclusion (decided: include).** The trade is backup
   completeness vs. import-side complexity (formatVersion bump, validator,
   preview, restore merge). If product later decides exports should stay
   "learning history only", reverting is contained to slice 4 — the document
   section is additive JSON. Note: no document tombstones exist, so restoring
   an older export can resurrect a document deleted *after* that export —
   acceptable v1 (documents never sync; rebirth-in-restore mirrors how a
   deleted phrase resurrects from a pre-tombstone export, which the existing
   tombstone machinery already limits).
2. **Scheduling-after-deletion (decided: stop).** Alternative (keep
   scheduling, or schedule *all* phrasebook entries) changes one predicate in
   `LibraryReview`; the "all phrasebook entries" variant is the natural
   follow-up feature and is deliberately out of scope ("imported phrases"
   only). Confirm the product stance on orphaned phrases at review.
3. **The 1 MB document cap** and the 200-char selection cap are named
   constants; both are guesses about reading ergonomics, not contracts.
4. **UITextView selection plumbing** (selection→callback) is the one piece of
   real UIKit work; the alternative tap-a-word fallback (reusing the
   `GlossableText` tokenization idea, `Glossary.swift:35-39`) loses multi-word
   phrases. Confirm the representable approach in slice 3.
5. **Widget/App Group: no.** Documents add nothing to the snapshot
   (`WidgetSnapshotWriter.swift:29-71`); the "no" from recon is confirmed.
6. **Paste/keyboard edge cases:** very long pastes (cap at 1 MB,
   validated on the same path as files), paste of rich text (clipboard's
   plain-text representation via `UIPasteboard.general.string`), and a paste
   containing only whitespace (rejected as `empty`).
7. **Spotlight:** saved phrases stay indexed (`SpotlightIndex.swift:92-123`);
   documents intentionally never are (§7).
8. **Library items in hands-free/flashcards modes** arrive for free (they are
   `ReviewItem`s); if TTS quality on learner text is poor, a mode-level opt-out
   can be added later — not in v1.
